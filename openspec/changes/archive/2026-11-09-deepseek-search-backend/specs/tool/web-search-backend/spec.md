## Purpose

搜索工具的后端选择与降级契约。目标是在不牺牲可用性的前提下引入官方自研搜索引擎的重排与权威度信号:单一后端故障不得导致搜索能力整体失效,付费后端的使用必须对调用方可见。

## ADDED Requirements

### Requirement: 后端选择优先级

搜索 SHALL 按"官方自研搜索引擎 → 本地后端"的顺序选择,且在官方后端不可用时自动降级而不使调用失败。

#### Scenario: 凭据可用时走官方后端

- **WHEN** 当前 provider 提供官方搜索引擎所需的 API key 与 base URL
- **THEN** 搜索 MUST 优先请求官方端点,不得先请求本地后端

#### Scenario: 无凭据时直接走本地后端

- **WHEN** 当前 provider 不提供官方端点所需凭据(如使用其他 provider)
- **THEN** 搜索 MUST 直接使用本地后端,且 MUST NOT 产生任何对官方端点的请求

#### Scenario: 官方端点失败时降级

- **WHEN** 官方端点返回限流、余额不足、服务端错误或超时
- **THEN** 搜索 MUST 在同一调用内降级到本地后端并返回其结果,而非直接向调用方报错

### Requirement: 搜索结果携带可信度信号

来自官方后端的结果 SHALL 携带重排分数、权威度与发布时间,供模型判断来源可信度;本地后端的结果 SHALL 明确表示这些信号不可用。

#### Scenario: 官方结果含可信度字段

- **WHEN** 结果来自官方后端
- **THEN** 每条结果 MUST 暴露重排分数与权威度,且在有发布时间时暴露日期

#### Scenario: 本地结果标注信号缺失

- **WHEN** 结果来自本地后端
- **THEN** 输出 MUST 不伪造可信度信号;调用方 MUST 能区分该结果未经重排

### Requirement: 降级不重复计费

一次搜索调用 SHALL 至多产生一次官方端点的计费请求。已知会导致计费失败的状态(余额不足)SHALL 在本次会话内不再重试官方端点。

#### Scenario: 余额不足后不再重试

- **WHEN** 官方端点返回表示余额不足的状态码
- **THEN** 本次调用 MUST 降级到本地后端,且同一会话内的后续搜索 MUST NOT 再次请求官方端点

#### Scenario: 限流走退避而非立即重试

- **WHEN** 官方端点返回限流状态
- **THEN** 该 host MUST 进入退避状态,在当前调用内直接降级到本地后端,不得立即重试官方端点

### Requirement: 付费后端使用可观测

搜索输出 SHALL 标明本次实际使用的后端,使付费调用次数可被用户与模型观察。

#### Scenario: 输出标注实际后端

- **WHEN** 搜索返回结果
- **THEN** 结果 MUST 包含一处标明实际后端的说明,且当实际使用付费后端时 MUST 可识别为付费来源
